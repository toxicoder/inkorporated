    NVIDIA DGX Spark Integration Plan¶

    What's on this page

    • Documentation for this infrastructure topic.

    What this enables

    • Operators can deploy and operate Inkorporated systems confidently.

    Overview¶

    This document outlines the technical implementation plan for integrating two NVIDIA DGX Spark systems into the Inkorporated homelab infrastructure. The DGX Spark systems, equipped with NVIDIA Grace CPU and Blackwell GPU architecture, will be added as dedicated GPU-accelerated worker nodes to the existing k3s Kubernetes cluster.

    Prerequisites¶

    Before integrating DGX Spark systems, the following infrastructure components must be deployed: 1. Longhorn Storage (Block storage for persistent volumes) 2. MetalLB (LoadBalancer provider for external services) 3. Observability Stack (Prometheus/Grafana/Loki for monitoring) 4. cert-manager (TLS automation) 5. MinIO Object Storage (Backup target)

    Phase 2: DGX Spark Integration¶

    Task 4.x: Integrate DGX Spark Systems as Worker Nodes¶

    Physical Setup¶
    1. Network Configuration
    2. Connect each DGX Spark system to the LAN switch via Ethernet
    3. Configure static IPs in management VLAN (e.g., 192.168.1.101/102 for DGX1/DGX2)
    4. Connect DGX nodes directly with two OSFP cables (200 Gbps each, 400 Gbps total)
    5. Assign private subnet for direct communication (e.g., 192.168.100.0/24)
    6. Configure jumbo frames (MTU=9000) for high throughput

    7. Bond interfaces for redundancy (Linux bonding driver)

    8. Security Configuration

    9. Update pfSense firewall rules to allow:
      • k3s API access (6443)
      • etcd communication (2379-2380)
      • Node ports (30000-32767)
    10. Configure DNS entries for DGX nodes (e.g., dgx-spark-1.inkorporated.local)
    11. Implement network segmentation per multi-zone topology
    Software Installation¶
    1. k3s Agent Installation
    2. Extend existing Ansible playbooks in infrastructure/ansible/
    3. Join DGX systems as worker nodes to the k3s cluster

    4. Install required dependencies: 

      apt update && apt upgrade -y
apt install curl iptables-persistent -y

    5. Node Configuration

    6. Label nodes for GPU scheduling: 
      kubectl label nodes dgx-spark-1 node-role.kubernetes.io/ai-gpu=true nvidia.com/gpu=true
kubectl label nodes dgx-spark-2 node-role.kubernetes.io/ai-gpu=true nvidia.com/gpu=true
    7. Taint nodes for GPU workloads: 
      kubectl taint nodes dgx-spark-1 dedicated=gpu:NoSchedule
kubectl taint nodes dgx-spark-2 dedicated=gpu:NoSchedule
    GPU Operator Deployment¶
    1. NVIDIA GPU Operator Installation
    2. Add NVIDIA Helm repository: 
      helm repo add nvidia https://helm.ngc.nvidia.com/nvidia
helm repo update

    3. Deploy GPU Operator: 

      helm install gpu-operator nvidia/gpu-operator \
  --set driver.enabled=true \
  --set devicePlugin.enabled=true \
  --set dcgm.enabled=true \
  --set dcgmExporter.enabled=true \
  --namespace nvidia-gpu-operator \
  --create-namespace

    4. Verification

    5. Verify GPU operator pods: 
      kubectl get pods -n nvidia-gpu-operator
    6. Test GPU detection: 
      kubectl run -it --rm --image=nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi

    Phase 3: AI Workload Configuration¶

    Update Existing AI Services to Use GPU Nodes¶

    1. Ollama Deployment

    2. Modify deployment to use node selector: 

      spec:
  template:
    spec:
      nodeSelector:
        node-role.kubernetes.io/ai-gpu: "true"
      tolerations:
      - key: "dedicated"
        operator: "Equal"
        value: "gpu"
        effect: "NoSchedule"

    3. Open WebUI Deployment

    4. Apply same node selector configuration

    5. Configure GPU resources in deployment spec: 

      resources:
  limits:
    nvidia.com/gpu: 1
  requests:
    nvidia.com/gpu: 1

    6. Langflow Deployment

    7. Configure node affinity and GPU resources
    8. Update deployment to target GPU worker nodes

    Storage Integration¶

    1. Longhorn Extension
    2. Deploy Longhorn agent on DGX nodes
    3. Configure local SSDs for volume replicas

    4. Create Longhorn storage class for AI workloads

    5. Persistent Volume Claims

    6. Update AI services to use Longhorn PVCs for model storage
    7. Configure storage size requirements for different AI workloads

    Phase 4: Monitoring and Testing¶

    GPU Metrics Monitoring¶

    1. DCGM Exporter Configuration
    2. Configure DCGM exporter to collect GPU metrics
    3. Set up Prometheus scrape configuration

    4. Create Grafana dashboards for GPU utilization

    5. Performance Testing

    6. Deploy test CUDA workloads to verify GPU functionality
    7. Run distributed training jobs to test inter-node communication
    8. Validate storage performance with AI datasets

    Security Implementation¶

    1. RBAC Policies
    2. Create role-based access controls for GPU resources
    3. Implement network policies for GPU node communication
    4. Configure Authentik integration for admin access

    Implementation Timeline¶

    • Week 1: Complete prerequisite infrastructure deployment (Longhorn, MetalLB, cert-manager, Observability)
    • Week 2: Physical setup and k3s agent installation on DGX systems
    • Week 3: GPU Operator deployment and AI service configuration
    • Week 4: Testing and performance validation

    Risk Mitigation¶

    1. Compatibility Risks
    2. Test DGX OS compatibility with k3s agent

    3. Verify NVIDIA driver versions with k3s cluster

    4. Performance Bottlenecks

    5. Monitor network throughput with iperf3 tests

    6. Validate GPU memory allocation and utilization

    7. Rollback Strategy

    8. Implement node draining for maintenance
    9. Maintain backup of existing configurations
    10. Document rollback procedures for each phase

    Resource Requirements¶

    • Hardware: 2x NVIDIA DGX Spark systems (Grace CPU + Blackwell GPU)
    • Network: 10/25/100 Gbps Ethernet connectivity, 400 Gbps direct OSFP links
    • Software:
    • k3s cluster (existing)
    • NVIDIA GPU Operator Helm chart
    • Longhorn storage operator
    • Prometheus/Grafana monitoring stack

    Success Criteria¶

    • DGX nodes successfully join k3s cluster as worker nodes
    • GPU Operator deployed and functional
    • AI services can be scheduled on GPU nodes
    • GPU metrics available through monitoring stack
    • Performance benchmarks meet expected throughput requirements
