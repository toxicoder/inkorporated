# Paths the secret scanner may report without failing the gate, each with the
# reason it is safe. One entry per line, `pattern<TAB>reason`. An entry with no
# reason is a failure, and --strict-ledger fails an entry that matches nothing.
#
# This ledger is where a false positive goes with an explanation. It is not
# where a real secret goes: a committed credential is removed and rotated.

.devcontainer/.env.example	template of placeholders, never a value; validated by //:validate_config_template
.devcontainer/cline_mcp_settings.json	non-secret MCP server configuration; secrets live in .devcontainer/.env, which git never sees
docs/requirements.txt	pinned package names, no credentials
package-lock.json	vendored dependency manifest; integrity hashes are not credentials
docs/interview_questions/*	interview question banks quote fictitious credential strings as review exercises
docs/engineering_standards/*	standards text shows what a leaked key looks like so reviewers can recognise one
